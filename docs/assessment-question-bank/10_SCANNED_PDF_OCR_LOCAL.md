# 扫描版 PDF 本地 OCR 与审题草稿

扫描版 PDF 没有可抽取的文字时，启用本地 OCR 后，解析任务把题目页以 2600 像素灰度图和单块阅读模式识别；进入“参考答案”附录后改用 2100 像素彩色图及默认分段模式，兼顾题干和密集答案。高分辨率页超时可在单页时限内回退到低分辨率识别。识别文字按题号与选项规则生成**待复核草稿**。原件、页面图片和 OCR 文字留在本机；不调用云 OCR 服务。系统保留原页预览和页号，所有 OCR 题的答案标为 `UNVERIFIED`。解析器可识别 OCR 丢失顿号的“二多项选择题”等标题；仅在前后题号明确时补回疑似误读的题号，并标记为重点核对；唯一匹配且能通过选项、题型和解析结论检查的答案会自动勾选，无法确认的答案只保留候选证据。管理员仍须核对 OCR 文字及来源授权，才能按现有题库流程建题及发布。

## 本地配置

需要 Node.js、`tesseract.js` 项目依赖、Poppler 的 `pdftoppm`，以及离线 `chi_sim.traineddata`、`eng.traineddata`。语言数据可从 [tessdata_fast 官方仓库](https://github.com/tesseract-ocr/tessdata_fast)获取，放在本机私有数据目录中的 `ocr-models` 子目录。先确认私有 PDF 导入只在隔离开发环境开启，再配置：

```text
NODE_ENV=development
QUESTION_PDF_LOCAL_IMPORT_ENABLED=1
QUESTION_PDF_OCR_ENABLED=1
QUESTION_PDF_OCR_DATA_DIR=<离线模型绝对路径>
QUESTION_PDFTOPPM_PATH=<pdftoppm 可执行文件绝对路径>
# 仅限本地隔离测试，按证据由单人确认机器处理权；生产环境忽略此开关
QUESTION_PDF_LOCAL_SINGLE_REVIEW_ENABLED=1
```

`QUESTION_PDF_OCR_ENABLED` 默认关闭。模型文件、原件、临时页图均不应提交到 Git。生产私有存储及安全扫描尚未接入，因此这套配置仅供本地隔离验证。

## 后台操作

1. 在“PDF 素材导入”上传原件并运行安全校验，点击该来源卡片上的“继续：核对授权”。
2. 授权页自动定位对应来源。按证据**只勾选“机器处理”**并提交声明；本地预览启用单人确认时，同一管理员可在待审声明填写审核说明，点击“本地确认机器处理”，然后点击“开始自动识题”。未开启该本地开关时仍须独立审核。缺少有效机器处理权时，解析任务停在 `WAIT_RIGHTS`，不会打开原件做 OCR。单人确认不授予题干展示、改编、商业访问或发布权。
3. 识题页自动带入来源 ID 和试卷名称，点击“自动识题并生成待审草稿”。后台需要 `node scripts/dispatch_question_parse.js --loop` 处理队列；页面会每 5 秒刷新排队/解析中的任务。若扫描页需 OCR，任务解析器版本为 `hybrid-pdf-ocr-v5`，会按答案页内章节顺序匹配题号；唯一匹配且选项完整的答案自动勾选，仍标为 OCR 待核对。冲突、缺项、疑似误读题号或截断内容不自动填入。新版 OCR 使用更清晰的灰度页图，因此单页处理时间可能增加；达到时间上限时可按现有检查点重试。
4. 任务进入 `WAIT_REVIEW` 后逐题查看原页和草稿。可点“保存并看下一题”顺序校对；草稿保存后点“用已保存草稿填入题库”，题库页会重新按管理员权限读取草稿并预填题干、选项、答案、解析及 PDF 来源与页码。OCR 的字符、选项及答案均可能出错，题库表单仍需人工核对；保存为题库修订后继续现有的独立内容与权利审核。题集页可一次粘贴多个修订 ID 加入草稿，再由服务端逐题检查后标记内部 ready，免费公开仍需单独开放并实时核验授权。`WAIT_OCR` 表示 OCR 未开启、模型/渲染器缺失、超时，或有页面仍无识别文字；按提示修复后重试。单次处理达到时间上限会保存页级检查点，重试继续。

曾以 `digital-pdf-v1` 创建的旧任务不能直接切换 OCR 模式复用检查点；启用 OCR 后请在后台新建任务。对于同一来源和试卷版本，系统按解析器版本区分任务。

## 已验证范围

本地合成扫描题 PDF 完成“渲染 → 中文/英文 OCR → 切题草稿”链路。测试中选项“乙”曾被识为“G”，因此草稿和答案必须人工核对原页。扫描页可能有双栏、图表、跨页题干、低清晰度和答案错位；规则解析不保证每页都能切题。未取得有效机器处理权益的真实来源仍由门禁拦截。
