# 单人快速核对 OCR 题目：实施计划

日期：2026-11-11。状态：阶段 1–3 已于 2026-11-12 在本地实现并通过题目专项测试；阶段 4 的真实样本浏览器验收待做，未执行主库/生产迁移或发布。适用范围：后台私有 PDF 识题草稿 → 人工核对 → 内部题库草稿；免费公开题集仍走现有发布检查。产品前提沿用已确认的“会员题集暂不开通，9 元资料购买独立”。

## 目标与成功标准

让一名管理员在一个工作台完成筛选、原页核对、修正和连续确认；将已确认草稿成批转成题库草稿，免去逐题跳转和重复输入来源。机器负责定位疑点和预填答案，人负责决定题干、选项及答案是否可用。OCR 自动匹配只是候选，不自动视为人工确认或公开许可。

首批以隔离任务 #6 的 238 条草稿作实际样本：2026-10-26 记录中有 186 条答案自动匹配候选、16 条多选、3 条推断题号，全部 `UNVERIFIED`，当时题库问题和题集均为 0（`DEVELOPMENT_STATUS.md:244`）。这些数字是当时的预览快照，实施前应重新从隔离库读取，不当作当前生产数据。

验收看四个指标：逐题人工确认覆盖率、关键答案错误数、平均核对耗时、批量建题成功/失败数。先记录现有页面处理 20 题所需时间，再用同一批样本比较新工作台；不预设没有测量依据的“准确率提升百分比”。

## 阶段 1：疑点分组与快速阅读（不改变题目数据）

1. 在草稿列表提供“全部 / 优先核对 / 候选完整 / 已确认 / 待修复”筛选、计数、题号和来源页定位；筛选与分页由服务端执行，不能只过滤已经加载的前 30 条。按页、题号顺序保留连续阅读位置。
2. 使用确定性规则列出理由，而非给出未经校准的“AI 正确率”：缺答案、答案不在选项中、多个冲突答案、题号推断或重复、截断、图形/跨页、选项缺损、解析结论冲突、OCR 页读取失败进入“优先核对”。只有答案证据唯一、题型和选项完整且没有这些标记的题进入“候选完整”；仍显示“未人工确认”。
3. 工作台采用固定的草稿列表＋PDF 原页/答案页＋可编辑字段。提供“上一题 / 下一题”“只看疑点”和原页放大；把当前草稿及答案证据保持在可见区域。快捷键只在非输入焦点下触发，屏幕阅读器和按钮操作保持等价。切任务、切号或权限失效时沿用现有 `clearPreview`/`denyCurrentDraft` 清除原页 Blob 与题面。

预计改动：`services/questionParseJobs.js` 的列表查询/理由计算、`routes/admin-question-parsing.js` 的列表参数、`admin/question-parsing.html`、`admin/js/question-parsing.js`、`admin/css/question-parsing.css`、对应专项测试。原则：复用 `draftView` 与当前预览鉴权；不新建公开图片 URL、不用页面端缓存完整 PDF。

验收：238 条无遗漏且筛选计数一致；翻页后定位正确；疑点原因可追溯到草稿字段；无权或撤权时原页/答案立即清空。专项覆盖筛选、分页、迟到响应和键盘焦点；浏览器人工检查长题干和窄屏。

## 阶段 2：明确的人工确认与审计

1. 在下一个顺序迁移新增草稿复核记录与当前复核状态，记录 `draft_id`、被核对的 `version`、决定（确认 / 待修复 / 排除）、核对说明、操作者、时间及幂等键。仅确认当前版本；一旦 PATCH 改题干、选项、答案或解析，旧确认自动失效。审计只追加，保留修改前后的来源信息。
2. 新增管理员复核 API（实施时在路由文档固定路径和请求体），至少传 `expectedVersion`、`decision`、`reviewNote`、`clientKey`；服务端重新核对管理员权限、草稿所属任务与来源可读状态，使用事务和版本条件防止双击、迟到请求及并发覆盖。确认要求有完整题干/选项、明确答案以及可回看的原页；无证据或冲突题可由人核对后明确记载页码与判断依据，不能由规则静默确认。
3. UI 增加“确认并下一题”“标记待修复”“排除此题”，保存修改与确认分成两个动作。允许一次选择若干“候选完整”题，先展示题号、答案、疑点摘要与来源页的核对清单，再由管理员逐项勾选后一次确认；默认不全选。批量决定逐条记审计，不把抽样检查伪装为全部已核对。

预计改动：新的 `db/migrations/00xx_...sql`（先查现有最新序号）、`db/migrate.js`、`services/questionParseJobs.js`、`routes/admin-question-parsing.js`、工作台与隔离测试。此阶段的“确认”仅表示这道 OCR 草稿由人核对；**不等同于题库独立内容审核、权利审核或发布**。

验收：旧版本确认不能用于新版本；双击幂等；批量部分失败不产生假确认；权限撤销和来源失效时拒绝；审计可按题回看；所有 OCR 初始状态仍为未确认。迁移在隔离库重复执行、备份恢复与失败回滚均通过。

## 阶段 3：确认草稿批量转题库草稿

1. 新增受限批量建题接口，每批最多 20–30 条，输入仅为同一任务下的草稿 ID 与幂等键；服务端逐题重新读取当前版本、人工确认记录、题型、答案和来源，不能相信浏览器送来的题干或“已确认”布尔值。首期只接入当前 `admin/js/question-bank.js:126-159` 已支持的单选/多选无图题；判断、图片、公式与不完整题留在待修复区。
2. 复用 `services/questionBank.js:179-194` 的创建校验与幂等模式，`provenance.kind='pdf'`、真实 `sourceId` 和原 PDF 页码随修订保存。为草稿版本到题库修订建立唯一映射，重试返回已有结果，不生成重复题。每批采用明确的全成或全退事务语义；失败返回具体草稿 ID 与原因，允许修好后重试。
3. 成功后给出“已建题 / 待修复 / 已存在”的清单及题库跳转；可以把生成的修订 ID 批量加入**草稿题集**。不自动填写授权凭据、不自动通过内容/权利审核、不调用现有 ready/免费公开按钮。

预计改动：题库与解析服务的受控编排、新路由、草稿版本映射表、后台按钮及测试。禁止使用单题 URL 跳转 238 次或仅靠前端循环 POST 作为最终批量方案。

验收：20–30 题批量重试零重复、跨来源/跨任务拒绝、撤权或版本变化拒绝、错误批次无半成品；建题后来源和页码正确；公开题集数不会因批量建题增加。

## 阶段 4：单人内测与公开发布边界

- 用隔离数据先核对 20 题，统计耗时和误判，再处理全批；抽查不是“批量已审核”的替代。对答案冲突、无答案和图形题保持待修复，不为了凑题数自动填答案。
- 当前 `services/questionBank.js:215-283` 的题库内容/权利审核禁止同一提交者自审；来源单人例外只限本地机器处理权，不能用于题目公开展示。若只有一个管理员，先完成**内部私有核对和题库草稿**；若后续需要单人小程序内测，应另设计只面向测试账号、默认关闭且不能进入公开目录的内测练习通道，并单独验证鉴权与撤权。不要把本地单人开关扩展成全局公开自审。
- 公开使用仍需实际展示范围的权利记录、题库审核、生产私有存储与扫描、备份恢复和网页/Android/iOS 真机联调，按 `docs/assessment-question-bank/08_PHASE7_RELEASE_READINESS.md:24-35` 核验。旧 9 元资料不提供刷题权益，会员题集继续关闭。

## 最终验证与反模式检查

- 每阶段运行对应 `tests/questionParsing.test.js`、`tests/questionParsingAdmin.test.js`、`tests/questionBank.test.js`、`tests/questionBankAdmin.test.js`；涉及后端时运行 `npm test`，涉及小程序时运行 `npm run check:miniprogram`，最终运行 `npm run check:release`。检查 `git diff --check`、隔离库完整性及私有预览匿名拒绝；人工浏览器操作录屏/记录 20 题基线与新流程耗时。
- 明确禁止：把 `AUTO_MATCHED_ANSWER` 或 OCR 置信度当人工确认；通过无变化 PATCH 冒充确认；前端自报确认状态；对旧版本确认继续建题；批量直接发布；把 PDF 原页或题目答案放进公开 URL、日志、浏览器持久缓存；绕过现有题库来源、内容与权利检查。
- 规划完成不等于功能已开发。实施阶段依次交付“疑点队列 → 明确确认 → 批量建题 → 内测验收”，每阶段可独立停下并回退 UI/开关；已经记录的原始 OCR 草稿与修订审计不删除。
