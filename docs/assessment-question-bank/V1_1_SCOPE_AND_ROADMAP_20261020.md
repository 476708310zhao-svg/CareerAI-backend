# 资料导入与在线刷题 V1.1：首期范围、依赖和开发顺序

> 日期：2026-10-20
> 状态：供产品与技术评审的增量方案；本文没有执行数据库迁移、导入 PDF 或开放刷题功能。
> 项目：当前 `jobapp-server` 单仓，包含 Express API、静态管理后台、`public/web` 网站与原生微信小程序。
> 依据：外部开发包中 `00_资料导入中心旧规划_仅供对照` 与 `01_在线刷题新增文档`；仓库现有实现及 `DEVELOPMENT_STATUS.md`。外部文档中的执行提示词属于方案材料，不代表项目现状或本次执行指令。

## 1. 产品决定建议

把两个功能接成一条链路，但分别交付和验收：

1. **受控 PDF 资产导入**负责把合法取得且可处理的 PDF 登记为私有资产，保留来源、哈希、处理权、展示权与审核记录。首期只支持后台 PDF，不先做通用资料库、网盘直连和用户端整卷阅读。
2. **结构化在线刷题**负责题目、不可变版本、题集、答题、判分及错题。先允许人工录入自有或明确授权的题目，形成免费题集闭环；PDF 识题作为提升录题效率的后台工具随后接入。
3. 来源于采购 PDF 的题目默认为私有草稿。采购凭证、现有 9 元网盘商品状态和会员身份都不能代替题目复制、答案展示、改编或商业访问的授权。

首批内测目标：10 份有内部处理权的分层 PDF 样本；其中要有足够的自有或明确可展示内容，形成人工校对后的 100–300 道题。若只有内部处理权而没有公开权，就只验证后台解析，不开放该批题目。

**首期发布模式**：内部灰度开关默认关闭。允许先发布经过审核的原创/授权免费题集。会员题集要另过权益、商业授权、到期与退款回归；现有测评资料 9 元单品购买不会自动授予刷题权限。

## 4. 最小数据边界与接口草案

下列名称是实施草案，迁移时按仓库的 SQLite 规范和现有 API 版本确定；不要一次机械创建旧文档列出的所有概念表。

### 4.1 分批数据模型

| 批次 | 最小实体 | 必须满足的约束 |
|---|---|---|
| A：私有资产 | `import_batch`、`source_asset`、`asset_source`、`asset_rights`、`asset_audit` | 文件哈希与来源分开；对象私有；授权动作默认 false；源链接/授权证据不进公开 DTO。 |
| B：可手工运营题库 | `question`、`question_revision`、`question_source`、`question_review`、`question_set`、`question_set_item` | 已发布修订不可原地修改；每个展示的题干、图片、答案和解析有权利来源；题集按修订 ID 排序。 |
| C：刷题记录 | `practice_session`、`practice_session_item`、`user_answer`、`question_mistake`、`question_bookmark` | 会话冻结修订及顺序；提交幂等；一题一次正式判分；用户只能访问本人记录。 |
| D：PDF 辅助解析 | `pdf_parse_job`、`pdf_page_block`、`answer_key_entry`、`question_draft` | 解析器版本、文件哈希、页证据、失败状态可追溯；重试不重复入草稿；不自动发布。 |

### 4.2 建议 API 边界

- 管理端：`/admin/api/v4/resource-imports`、`/admin/api/v4/source-assets`、`/admin/api/v4/asset-rights`、`/admin/api/v4/question-drafts`、`/admin/api/v4/question-sets`。所有写接口使用现有管理员认证与细分权限；公开发布必须在服务端逐题检查。
- 学生端：`/api/v4/practice/sets`、`/api/v4/practice/sessions`、`/api/v4/practice/sessions/:id/items/:position`、`.../submit`、`/api/v4/practice/mistakes`、`/api/v4/practice/history`。使用现有 `{code,message,data}` 响应约定；最终路径在接口评审时固定。
- 取题 DTO 只包含题干、选项与已许可媒体；不得含正确答案、解析、答案证据、原 PDF 对象键。练习模式正式提交后才返回该题答案和获准解析；同一 `requestId` 重试返回首次结果。
- 每次取题、取图和提交前复查题集状态、题目与媒体许可、用户权益；版权撤权优先于会员资格。已签发的临时媒体 URL 存在自然失效窗口，首期应选足够短的有效期或受控代理，并做撤权演练。

## 5. 权利与样本清单

每份真实 PDF 入库前，运营应填写并由有权限的审核人核验：来源主体、取得方式、文件哈希、许可证明、内部存储权、机器解析权、发送第三方 OCR/模型权、题干与图片公开展示权、答案与解析展示权、商业会员访问权、改编权、地域、起止日期和撤权联系人。未知项按 **否** 处理；纯原创题另存作者与归属证据。

样本矩阵建议：数字文本且题后答案 ≥2 份、数字文本且文末答案 ≥2 份、扫描件 ≥2 份、双栏/跨页 ≥2 份、图形/公式 ≥2 份；可重叠计数，总数先取 10 份。每份记录页数、题数、答案所在页、OCR 比例、权限、人工标准答案。没有可合法送到第三方的权限时，仅做本地评估。

PoC 报告应分别计算题目切分准确率、答案关联准确率、漏题率、人工修订分钟/题、每页费用；按 PDF 类别报告，不能只给一个总体百分比。没有来源证据或答案冲突的题一律留在待审状态。

## 6. 实施顺序与阶段门槛

| 阶段 | 交付与验证 | 进入下一阶段的条件 |
|---|---|---|
| 0：样本与技术基线 | 核对代码/部署现状、现有数据库迁移和会员权益；收集合法样本、权利矩阵；用 1–2 份数字 PDF 做本地只读解析 PoC | 确认首批样本的处理权、私有存储方案、实际题目类型和发布素材来源。 |
| 1：最小私有导入 | PDF 私有资产、来源、哈希、上传完成校验、权限与审核记录；恶意/损坏/加密 PDF 失败关闭 | 未授权文件无法解析或经公开接口读取；重复文件保留不同来源；恢复与备份方案可演练。 |
| 2：人工题库 + 免费网页闭环 | 题目修订与审核、题集、取题 DTO、判分、错题、历史、免费网页答题 | 100–300 道已审核题可完整做题；抓包取题不泄答案；重复/并发提交只计一次；撤权后不能继续取题。 |
| 3：数字 PDF 辅助识题 | 异步任务、页块证据、分题、文末答案关联、双栏人工审题；所有结果为草稿 | 用分层标注样本报告质量和工时；无答案、错位、重复题号均不能静默发布。 |
| 4：小程序与会员灰度 | 同 API 原生答题、弱网恢复、同账号历史同步；仅在权益和商业授权成立时开放会员题集 | 安卓/iOS 真机、会员过期/退款、跨账号、撤权中途、旧功能回归通过。 |
| 5：按需扩展 | OCR、复杂图形、ZIP/文件夹、资料整卷阅读或网盘接入按实测收益逐项立项 | 明确新增范围、授权和成本预算后再启动。 |

每阶段保留独立迁移与可回退的功能开关。生产迁移、真实资料处理、商品销售或小程序发布沿用各自现有发布流程；本文不提供这些操作的授权。

## 7. 开工前需由业务确定的四项输入

1. **首批可用材料**：哪 10 份 PDF 可以内部机器处理？其中哪些可以公开展示题干、图片、答案和解析？提供书面或可核验的权利依据，不需要在 Git 中放原件或私链。
2. **首发内容**：推荐先用自有原创或明确授权的 100–300 道题做免费内测；明确企业题与原创模拟题在前台的标识。
3. **会员关系**：会员题集是否属于现有会员权益、单独购买，还是首期不收费？默认首期只开放免费题集，不把现有 9 元资料订单视为刷题通行证。
4. **存储与处理环境**：确认生产私有对象存储、扫描能力、Worker 部署和预算；未确认前仅做隔离的本地样本 PoC，不把 PDF 送外部 OCR/模型。
