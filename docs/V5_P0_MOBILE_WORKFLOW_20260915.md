| 页面 | 用户现在可以做什么 |
|---|---|
| 找岗位 | 点击收藏、加入待投递或查看进度；校招日历保留；加载失败可以重试 |
| 岗位详情 | 收藏、AI 匹配、待投递、复制官方申请链接；复制链接保持待投递，不代表正式投递完成 |

| 我的 | 进入完整求职工具与资源目录，承接原资源 Tab 的功能 |

## 做减法的范围

进度列表移除申请漏斗、重复工具宫格和材料准备度。材料准备度以前把截止日期也计为材料完成，容易误导用户。申请详情和历史材料数据保留。

岗位详情移除独立模拟面试/复杂规划推荐块。相关能力仍可通过资源目录等既有入口使用。底部聚焦收藏、匹配、待投递、去申请。

详情页收藏不再额外写入申请，避免一次收藏覆盖已有申请状态。收藏与待投递保持两个明确动作；前者走现有收藏同步，后者写唯一申请。存量申请不删除。

## 数据与接口兼容

| 用途 | 既有接口/字段 |
|---|---|
| 加入待投递 | POST `/api/v4/applications`，`status: preparing` |
| 处理重复创建 | 409 的 `data.applicationId` → GET `/:id/detail` |
| 已收藏推进待投递 | PATCH `/:id/status`，仅 interested → preparing |
| 改状态 | PATCH `/:id/status`，使用 `allowedTransitions` 和 `expectedState: {status, historyId}` |
| 查看全量进度 | GET `/api/v4/applications/board`；小程序从 applied 组拆出 OA 展示，不改服务器分组 |
| 本机兼容 | 保留旧记录；V4 preparing 映射旧 online_apply，但显示为待投递 |

不新增后端字段或路由。OA、正式投递、电话面试、各轮面试、Offer 保留现有状态值。终态不会被重复“加入待投递”重置。

保存失败不会提示云端成功。请求期间更换账号时不回写旧账号结果。正式投递需要用户完成外部申请后在进度页明确标记。

## 真机验收路径

1. 找岗位 → 校招日历；确认入口不遮挡搜索或岗位列表，返回 Tab 正常。
2. 未登录点待投递 → 当前页登录弹层 → 登录成功继续原动作。
3. 连续点击同一岗位待投递 → 只有一条申请；再点查看进度。
4. 进度页将待投递改为已投递，再改为 OA；检查计数和 OA 筛选。
5. 返回岗位列表和详情，状态一致；收藏不会把已有面试/Offer 变回待投递。
6. 岗位详情保存并复制链接 → 进度保持待投递；在浏览器正式申请后再手动更新。
7. 弱网下加载和保存失败能重试；新增申请内容不丢失；触底分页失败不删除已加载岗位。
8. 我的 → 求职工具与资源，确认原资源目录仍可访问。
