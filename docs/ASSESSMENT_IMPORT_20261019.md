## 可信来源与范围

- 用户提供的飞书完整快照有 40 行；京东、美团、百度、拼多多、小米 5 行有资料分享，其余 35 行跳过。
- `assessment-import-profile-20261019.json` 仅包含公开公司名称、可信 slug、封面和 900 分 SKU 映射，无网盘地址和提取码。
- 微信道具对应本会话成功上传的修正版工作簿，用户已确认发布到线上；这不是独立微信后台/API 对价格和可购状态的审计。
- `assessment-shared-instructions-20261019.json` 保存用户确认的四段通用说明（含温馨提示），显式传入时一次初始化。不在每个商品重复保存；已有其他内容时拒绝覆盖，应通过带版本确认的管理后台修改。
- 临时飞书原文、含私链的数据库、备份和日志不得进入 Git、发布静态目录或公开商品响应。

## 导入边界

`services/assessmentImport.js` 注入显式数据库连接，不加载启动数据库、dotenv、支付服务或运行 DDL。0015 只创建私有来源绑定表，不修改已付订单、快照或账本。

- 仅抽取唯一 `https://pan.baidu.com/s/...` 地址，Markdown 同一地址的重复展示去重；`pwd` 如存在必须为四位字母/数字，与正文提取码一致。存储地址和提取码分离。
- 不接受 HTTP、多不同分享地址、陌生域名/参数、混淆域名、脚本及不完整分页快照；错误和摘要不回显原文/私链/码。
- 公司按公开 profile 的 slug 与允许名称校验并复用，不硬编码数据库 ID。拼多多缺失时只建真实名称、slug 和导入来源的最小草稿公司，不编行业、官网、简介或 Logo。
- 导入新建公司来源为 `assessment-feishu-import`，在明确发布公司前，对公开公司列表/详情及用户职位详情隐藏（包含草稿、归档或空状态）；管理员仍可查询和编辑。编辑、保存或归档不会移除该来源标记；仅显式 `data_status=published` 才恢复公开可见。这个窄边界不改变其他历史来源草稿的既有可见性，也不等于测评商品上架。
- 新商品和更新都只保存草稿，不启用首页、不触碰支付配置；未知领取期限为 `null`，不推定一年有效。
- 原表没有实际目录；目前文案只引用分享记录的文件名称，不把名称当成已核验目录。目录提示“具体文件以网盘实际目录为准”，私有绑定 `content_needs_review=1`。需人工核验文件、来源权利、目录和交付可用性后，才可在管理后台另行上架；导入器没有上架或绕过审核参数。
- 来源以 `source_namespace + Feishu record_id` 唯一；同源重跑不重复创建、不重复更新说明。不同源或手工商品占用相同 SKU 时拒绝，不按标题自动接管。
- 同源变更仅更新尚未人工修改的草稿；已上架/下架产品变更必须走后台审核，不自动改为草稿。人工修改过的字段产生冲突时保留人工数据并拒绝覆盖。
- 首次初始化共享说明按既有规则关闭资料待付订单；已付快照、领取记录、账本和会员不变。重跑相同说明不再关闭待付。

## 操作方式（示例，非本次已执行的生产命令）

先将原始快照放在仓库外的受控私有路径；数据库和输入均必须是存在的绝对路径。CLI 不猜测运行库、不读取 `.env`，默认只读，正式迁移必须独立备份和审批后完成。

```text
node scripts/import_assessment_resources.js --db=<绝对数据库路径> --source=<仓库外私有快照JSON绝对路径> --profile=<公开profile绝对路径> --instructions=<已确认统一说明JSON绝对路径> --target=local
```

先审阅脱敏 dry-run 的行数、公司动作、价格、SKU 和待审状态。写入时额外提供：

```text
--apply --confirm=IMPORT_ASSESSMENT_DRAFTS --confirm-target=<数据库realpath原样> --backup=<仓库外尚不存在的新备份绝对路径>
```

CLI 首先只读验证 schema 迁移状态、完整性与导入计划；随后生成新的在线 SQLite 备份，验证备份完整性、外键、迁移状态并记录 SHA-256，再打开写连接，在 IMMEDIATE 事务内重新规划并写入；任意商品失败时整批说明、公司、商品、绑定及审计回滚。备份文件不覆盖。

生产必须另行获得用户对**明确生产目标、迁移和导入**的授权并安排维护窗口，才可使用 `--target=production --production-approved --maintenance-confirmed`。这些参数仅记录已存在的审批和维护决策，绝不代替用户授权；生产 `NODE_ENV` 不允许伪装为 local/staging。数据库备份恢复应由既有运维流程在停止写入后执行，切勿覆盖正在运行的数据库。

实际商品上架、首页三家公司选择、商户配置、回调/真机验收、收款门禁及小程序发布都是独立流程，本 CLI 不执行。当前用户只确认了微信道具发布，不能据此声称小程序商品已上线或真实支付已验收。
