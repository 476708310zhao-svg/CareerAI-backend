# 学生求职流程与机构服务：现状差距和后续规划

更新时间：2026-11-17。适用基线：`codex/release-20261116`。本文依据用户提供的两张截图、当前仓库代码和现有产品文档制定；**代码有入口不等于线上已发布，也不等于服务已真实交付**。2026-11-16 的发布记录明确：仅后端发布，小程序客户端尚未上传体验版或提审（`DEVELOPMENT_STATUS.md`）。网页端与小程序的实际可用性、数据覆盖和 AI 输出质量须另行验收。

## 一、规划结论

1. 用同一条 `application` 串起“岗位、匹配证据、简历版本、材料、官网投递确认、OA、面试、Offer、下一步任务”，允许步骤跳过、倒序和重复。OA 可能在不同招聘阶段出现，不能做成强制八步闯关。
2. 小程序负责发现、提醒、快速确认和碎片练习；Web 负责材料编辑、批量管理、长内容复盘和 Offer 详细比较；运营后台负责来源核验、内容与人工服务交付。共享后端记录，不让本地缓存成为跨端主数据。
3. 先补齐已有能力之间的连接，再试点人工服务。竞品的“导师一对一、内推、实习保障、课程数量、证书”不能因机构资料展示或自助项目工具存在，就写成职引的现有承诺。
4. 首批验收建议选一个明确人群与岗位簇，例如“2027 届英语地区软件工程应届岗位”。这只是试点建议，不把美国示例的工作资格规则推广到全球。国家、学历、岗位、语言和服务供给范围由产品负责人在实施前确定。

## 四、执行阶段

优先级：P0 = 完成一次真实求职申请的必要闭环；P1 = 提高训练与反馈质量；P2 = Offer 与人工服务深度。阶段按验收门槛推进，不以截图中机构套餐的功能数量作为目标。

### 阶段 0：文档发现与基线验收（P0，实施前）

- **做什么**：读取 `PRODUCT.md`、`docs/onboarding/01_CURRENT_STATE.md`、`V4_SPRINT4_CAREER_COACH.md`、`V4_SPRINT5_NETWORKING_COPILOT.md`、`V4_SPRINT6_OA_PROJECTS_JOB_TRUST.md`、`APPLICATION_ANSWER_DRAFTS_API.md`、`FUNNEL_ANALYTICS_CONTRACT.md`，并对照当前路由、前端调用与发布记录。定下试点人群/岗位簇，准备 3 条可复测的真实样例申请和脱敏材料。
- **允许直接沿用的 API/模式**：`GET /api/v4/jobs`、`POST /api/v4/jobs/:id/match`；`/api/v4/applications` 的创建、工作区、任务、联系人、提交确认；`/api/v4/resumes` 版本与确认写入；`/api/v4/materials` 草稿与确认；`/api/v4/oa` 计划/场次/错题；`/api/v4/interviews` 面试空间；`/api/v4/projects` 证据项目；`/api/v4/networking` 联系人草稿。实际请求体以对应路由和前端封装为准，不在计划中假造新参数。
- **验收**：用现有发布分支、已部署后端、微信体验版、Web 各自记录版本和功能证据；一份覆盖八步的端到端检查表标记“通过/未通过/未验证”。
- **防错**：不引用旧 `main` 或历史 5.0 方案作为现状；不把源码页面、后端接口、微信线上版本和人工服务交付混为一谈。

### 阶段 1：申请主线与跨端主数据（P0）

- **做什么**：以 `application` 为唯一业务主线，把目标岗位、JD/来源、匹配证据、下一步动作、截止日、简历版本、材料清单与提交证据接在同一工作区；Web 接通简历/材料完整编辑与确认，小程序强化随手确认和待办；将 Offer 本地缓存逐步迁到后端结构化记录，保留旧数据迁移与回退方案。
- **照着做的参照**：产品边界 `PRODUCT.md:17-45`；申请操作 `routes/v4/applications.js:193-327,336-365,440-455`；简历版本/变更确认 `routes/v4/resumes.js:163-232,331-394`；材料草稿/确认 `routes/v4/materials.js:332,389-427`；Web 现有申请编辑 `public/web/applications.js:145-182`；小程序接口封装 `miniprogram/utils/api-v4.js:28-64,121-171`。
- **验收**：同一账号从小程序加入岗位、Web 编辑材料、回小程序查看并确认官网提交；另一账号不可读写；版本与草稿可追溯；断网/重复点击不会生成假提交。网页端所有显示为“可做”的材料操作必须真的可用，否则诚实空态。
- **防错**：官网链接点击、职引内保存、用户确认投递、企业回执是不同事实；不自动填表/投递，不静默写入 AI 草稿，不用本地 `localApplications` 作 Offer 唯一数据源。

### 阶段 2：按申请驱动的 OA 与面试循环（P1）

- **做什么**：根据 JD 与申请截止日推荐 OA 类型、短期训练计划、错题复练；模拟面试使用岗位与简历版本；真实面试记录独立于模拟报告，复盘后生成下一步任务。Web 补充长内容练习与复盘，小程序保留随时练和快速记录。
- **照着做的参照**：`V4_SPRINT6_OA_PROJECTS_JOB_TRUST.md`、`miniprogram/utils/api-v4.js:173-182,212-218`、`routes/v4/interviews.js:18-114`、`public/web/practice.js`、`miniprogram/package-ai/pages/interview-notebook/`、`routes/v4/applications.js:473-496`。
- **验收**：从一条申请创建训练计划，完成练习/模拟，查看错题与报告，记下真实面试，生成并完成后续任务；题目授权和内容来源抽样复核；Web/小程序数据一致。
- **防错**：不把自报 OA 成绩当系统评分，不把模拟反馈当企业评价，不承诺题库命中或考试通过。

### 阶段 3：Offer 决策与人工服务小规模试点（P2）

- **做什么**：建设跨端 Offer 资料、比较与决策留痕；先以已有三类工单建立明确交付标准和运营后台质检。只有在导师供给与服务流程可验证后，才开预约、导师陪跑或真人模拟试点；项目证据导出与外部转介分开设计。
- **照着做的参照**：本地 Offer 页 `miniprogram/package-career/pages/offer-compare/offer-compare.js`、工作区未集成状态 `services/v4ApplicationWorkspace.js:81-82`、人工工单 `services/manualServiceRequests.js` 与 `routes/v4/manual-services.js`、后台 `admin/js/manual-services.js`、项目证据 `services/v4ProjectBuilder.js:252-306`。
- **验收**：两份 Offer 跨端录入/比较、币种与未知项明确、原始文件只对本人可见、决策可修改并留痕；服务工单从授权到交付、撤销和申诉有可审计样例；人工服务满意度由真实用户反馈。
- **防错**：不推断税后薪酬或工作资格；不宣称 Offer 保证、内推保证、企业证书或付费实习；涉及收费和英国/其他地区转介时先做法务与运营审查。

### 阶段 4：最终验证与是否扩展课程/社群的决策

- **做什么**：按阶段 0 的文档和真实 API 逐项核对实现；检查旧入口兼容、账号隔离、授权/确认、幂等、页面文案；运行相关专项、`npm run check:miniprogram`、`npm run check:release`、`npm run check:acceptance -- --no-report`，并单独完成微信体验版真机与 Web 浏览器人工验收。后端变更按 `AGENTS.md` 至少跑 `npm test`。扩展课程/社群前先评估实际内容供给、版权、完课、答疑负载和社区治理。
- **照着做的参照**：`AGENTS.md`、`README.md`、`docs/onboarding/01_CURRENT_STATE.md`、`FUNNEL_ANALYTICS_CONTRACT.md`，及各阶段引用的路由和页面。
- **验收**：保留版本号、测试报告、样例申请流程录屏/截图、内容抽检和服务交付记录；未验证项在对外文案中保持未开放。
- **防错**：全局搜索“自动投递、已获 Offer、保录、保实习、智能语义匹配”等绝对化文案并逐条核验；不得只凭测试通过宣称微信已上线或机构服务已经运营。

## 五、最小产品指标与拆分顺序

| 指标 | 定义与注意事项 |
|---|---|
| 岗位进入申请率 | 有来源且可用的岗位详情 → 用户创建申请；剔除重复与无效链接。 |
| 材料就绪率 | 申请中明确绑定简历版本、必需材料和清单确认的比例；不等于成功提交。 |
| 投递确认率 | 已创建申请 → 用户明确确认官网已提交；官网打开事件单独计数，企业回执单独记录。 |
| OA/面试循环完成率 | 用户完成一次训练/模拟 → 查看反馈 → 建立或完成下一步任务；区分真实面试与模拟。 |
| 服务交付质量 | 人工工单按约定时限完成、撤销/投诉、满意度；没有真实样本不报就业成功率。 |

建议先交付三个可分配任务：**A** 岗位到申请的跨端样例验收与来源/提交状态梳理；**B** Web 简历和材料编辑确认接通；**C** Offer 后端主数据与本地数据迁移设计。A 是 B/C 的验收基线；B 与 C 可由不同开发者在独立文件范围内进行，按 `docs/onboarding/03_COLLABORATION.md` 协作。其后再排 OA/面试闭环和人工服务试点。
