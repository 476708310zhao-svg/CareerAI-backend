## 购买能力补齐（2026-10-19，本地开发）

本节为后续购买能力修复；上文及后文保留原开发阶段记录，实际后端部署、草稿导入与首页配置分别见生产发布记录和首页启用记录。本次不部署、不修改环境开关、不发布小程序，真实收款尚未验收。

- 原因：资料购买复用了会员的 `IS_MOCK`，虚拟支付 Provider 已配置但会员月/季/年 SKU 缺失时，会错误地把独立资料商品判为不可购买或开发 Mock。
- 修复：Provider 基础凭据与会员 SKU 完整性分开判断。测评资料仅依赖所选渠道的基础配置，以及本品 SKU、虚拟支付通知 Token；不要求先配置会员 SKU。真实资料下单按资料能力确定 provider，使用原有签名和回调协议，不新增微信接口或参数。
- 保持原门禁：`PAYMENT_ENABLED` 关闭或未批准 `REAL_PAYMENT_LAUNCH_APPROVED` 时生产仍不可购买；未配置资料 SKU/通知 Token 时拒绝下单，不降级到 Mock。仅保留既有非生产、显式 `ENABLE_MOCK_PAYMENT=true` 的模拟开发通道，不把会员 `IS_MOCK` 用于资料真实付款。
- 会员隔离：保留 required SKU 门禁，并新增 `MEMBERSHIP_PAYMENT_ENABLED` 控制会员/场景包新销售；未设置默认 true 兼容原行为，显式 false 时配置接口关闭且服务端在写订单/账本前拒绝全部套餐。该开关不控制资料，也不阻止历史订单回调、查询或领取。只具备资料 SKU 不会打开会员销售。
- 未来仅资料收款配置顺序：先审核并部署本次代码，再明确设置 `MEMBERSHIP_PAYMENT_ENABLED=false`、核对资料渠道凭据及通知配置、保留真实环境禁止 Mock，最后在人工批准后设置全局 `PAYMENT_ENABLED=true` 和 `REAL_PAYMENT_LAUNCH_APPROVED=true`，并验收真机支付与回调交付。代码部署前不能直接打开全局开关；本次仅提供示例和流程，不执行上述生产操作。
- 交付与退款：真实资料订单不能经 Mock 确认；只有经过既有验签、900 分、单品 SKU、数量与订单渠道校验的服务端回调才能交付。停售或支付关闭不影响历史已付领取；记录完成外部退款后撤销领取。本次自动化仅用隔离数据库与合成回调，无真实收款或退款。
- 官方协议资料：本次尝试读取微信[虚拟支付能力](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment.html)与[requestVirtualPayment](https://developers.weixin.qq.com/miniprogram/dev/api/payment/wx.requestVirtualPayment.html)主文档均不可访问，因此未据第三方资料修改现有支付协议；真机及官方配置验收仍需后续完成。
- 专项验证：资料能力/支付/会员商业共45/45通过，0失败/0跳过；包含16项能力矩阵、无会员SKU时的真实virtual签名参数/Mock拒绝/合成回调/交付/退款闭环，以及全部会员/场景SKU已配但会员销售关闭时七个套餐拒绝且不写订单/账本、资料仍走真实virtual、未设置开关兼容旧行为。JS语法与差异格式检查通过。独立完整发布门禁另行记录，不代表生产按钮已开放或真机支付已通过。

## 已实现行为

- 首页“最新机会”下方复用列表卡片展示后台选定的最多 3 家不同公司及主推资料；资源中心、公司详情继续通向同一商品详情。
- 商品统一售价 ¥9.00（900 分）。后台编辑只读，新建即为 900 分；API 显式提交其它价格会被拒绝。首页、列表、详情显示服务端真实商品价格，新订单、购买快照及支付参数统一 900 分。会员和其它商品套餐不改价。
- 购买一个资料商品，服务端确认支付后才能在本人订单领取网盘链接与提取码；“我的已购”支持再次领取。
- 开发工具默认也读真实接口；没有商品则不展示首页热门卡片，资源中心保留“测评资料”入口，列表说明“资料正在整理中”。接口失败显示错误和重试，不自动塞示例。
- 正式版、体验版、真机始终不使用只读示例。仅开发者主动在模拟器 storage 设置 `assessmentPreviewMode=readonly-examples` 后重新启动，才可看带明显标记且不可购买的本地示例；移除该键后恢复真实接口。

真实物料尚未录入时，不存在可交付的三份正式商品；首页热门三条会在后台配置真实商品及关联公司后出现。本轮未生成或上架示例公司、示例网盘。

## 服务端定价与历史保护

`services/assessmentCommerce.js` 的 `PRICE_CENTS=900` 是本商品类别的价格规则。创建及编辑始终保存 900 分；请求中的其它价格被拒绝；客户端自带 `amount/priceCents` 不决定应付金额。下单仍校验 `expectedPriceCents`，过期报价拒绝创建订单。

新增 `0013_assessment_fixed_nine_yuan.sql`：

1. 全部现有测评资料（草稿/在售/下架）商品定价改为 900 分。
2. 仅取消非 900 分且仍为 pending 的资料订单，保留订单原金额及快照。
3. 原有 900 分待付订单继续有效。会员及其它类别待付订单不变。
4. 已支付/已退款订单、账本、交付、原购买快照不重写。

后续0014统一说明迁移覆盖第3项：所有资料待付款需重新确认共享说明，因此关闭资料待付（含900分），历史已付及会员不变。后台“统一说明”集中配置一次，单品继承并在新订单快照保存版本，详情过期版本不能下单。

0013 尚未应用时，新代码也会拒绝非 900 分旧商品下单并过滤公开列表/首页，避免部署先后顺序导致继续收旧价。旧价已付购买仍保留原记录和领取能力。旧价闭单后收到合法付款，按原订单金额核对并转为 `payment_review`，幂等记账、不交付，通过已有外部退款凭据流程处理。

不修改已应用的 0012 内容；迁移只由现有 runner 显式执行，不加启动自动 DDL。按 `DATABASE_MIGRATION_PLAN.md` 在后续正式发布时对明确目标做备份、状态检查、迁移及验收。源码更新不能代替数据库迁移。

## 后续飞书多维表格内容字段

本轮先使用现有管理后台录入。下表是后续用户提供资料时的字段约定，不表示已建立 Base、授权连接器、自动导入或实时同步。

| 表格列名 | 后台/服务字段 | 约定 |
|---|---|---|
| 公司名称 | `companyIds`，关联已有公司 | 必填，用于公司页及首页；先匹配公司库，未匹配先核对，不能随意造同名公司 |
| 资料名称 | `title` | 必填，购买和历史订单的识别名称 |
| 一句话简介 | `summary` | 必填，最多 200 字 |
| 封面链接 | `coverUrl` | 必填，可访问 HTTPS 图片或既有 `/uploads/` 路径 |
| 详细介绍 | `description` | 必填，纯文本 |
| 资料目录 | `catalogText` | 必填，每行一项 |
| 招聘季/适用届别 | `seasonLabel` | 可选 |
| 示例图链接 | `sampleImages` | 可选，最多 12 张 |
| 网盘名称 | `driveName` | 必填，如实际交付所用网盘 |
| 网盘链接 | `driveUrl` | 上架必填，完整 HTTPS 私密交付链接 |
| 提取码 | `extractionCode` | 网盘有密码则填，无密码留空 |
| 使用/领取/更新/售后四项说明 | 后台“统一说明”集中配置一次 | 不需在飞书每条商品添加四列；所有商品自动继承已确认的统一文案，未配置完整禁止上架/新收款 |
| 资料来源说明 | `sourceDescription` | 上架必填，采用实际来源 |
| 付款后可领取天数 | `claimDays` | 可选，正整数或空；空表示无平台领取截止日 |
| 微信虚拟支付商品 ID | `virtualProductId` | 可选，使用 virtual 渠道时上架收款前必须配置真实 9 元 SKU |
| 列表排序 | `sortOrder` | 可选，整数，小的优先 |
| 首页主推 | 首页配置 `items` | 可选，最多三家不同公司/商品，由后台确认并排序 |
| 售价 | 服务端常量 900 分 | 固定 9 元；不接受表格自定义金额 |

网盘链接和提取码只能放私密交付字段，不能混在公开介绍、目录或样例图里。建议先录为草稿，核对公司关联、目录与网盘可用性，再上架并选择三家主推。
