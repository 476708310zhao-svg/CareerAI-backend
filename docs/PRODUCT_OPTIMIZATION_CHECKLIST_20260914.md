# 职引小程序上线前功能优化清单

更新时间：2026-09-14

## 使用方式

这份清单面向正式用户较少的阶段。目标不是立即删除功能，而是先统一产品对象、入口和数据关系，再用小规模用户验证是否需要下线。资源中心继续完整直出，不做隐藏点击展开。

## 一、必须先做：统一核心对象和主流程

### 1. 明确五个核心对象

- [ ] 岗位：职位、公司、来源、JD、截止时间、匹配结果。
- [ ] 申请：一个岗位只能对应一个申请记录，包含收藏、投递状态、提醒、材料、面试和 Offer。
- [ ] 简历资产：基础经历、简历版本、ATS 检查结果、岗位定制内容。
- [ ] 求职计划：目标岗位、能力差距、阶段任务、完成证据。
- [ ] 面试记录：面试岗位、题目、回答、报告、错题和复盘。

### 2. 固定四条用户主线

- [ ] 找岗位：职位搜索 → 岗位详情 → JD 匹配 → 创建申请。
- [ ] 准备申请：申请记录 → 选择简历版本 → ATS 检查 → 生成申请材料。
- [ ] 跟进申请：申请管线 → 状态、截止提醒、联系人、面试和 Offer。
- [ ] 准备面试：面试记录 → 题库/STAR → 模拟 → 报告 → 错题复练。

### 3. 统一命名和下一步行动

- [ ] “普通简历”“简历中心”“申请材料”明确层级关系，避免并列造成选择困难。
- [ ] “求职进度”和“投递追踪”统一为“申请管线”或一个确定名称。
- [ ] “竞争力陪跑”“AI 求职规划”“技能路径”统一为“求职计划”的不同视图。
- [ ] 每个核心页面只突出一个主要下一步行动。
- [ ] 所有 AI 输出标明关联的岗位、申请、计划或面试记录。

## 二、第一优先级：合并简历与申请材料

- [ ] 以简历中心作为唯一简历资产底座。
- [ ] 普通简历入口改为跳转到简历中心，不再维护第二套数据。
- [ ] ATS 检查绑定“简历版本 + 目标岗位”。
- [ ] JD 匹配结果可以直接创建申请记录。
- [ ] 申请记录增加“申请包”区域，集中显示简历、ATS 结果和申请文案。
- [ ] 允许一份基础经历生成多个岗位版本，但明确标注适用岗位。
- [ ] 旧入口暂时保留兼容跳转，确认数据稳定后再考虑移除。

## 三、第二优先级：统一申请管线

- [ ] 每个岗位只允许一个主申请记录，避免重复投递记录。
- [ ] 统一状态：已收藏、准备中、已投递、笔试中、面试中、已录用、已结束。
- [ ] 状态变化自动生成下一步任务和截止提醒。
- [ ] 岗位详情、首页提醒、每日简报和进度页都指向同一申请记录。
- [ ] 联系人、Networking 记录、面试结果和 Offer 决策挂在申请下。
- [ ] 统一收藏、投递追踪和求职进度的数据来源。

## 四、第三优先级：合并规划体系

- [ ] 只保留一份求职计划数据。
- [ ] 竞争力诊断负责生成能力差距。
- [ ] AI 规划负责生成或调整阶段任务。
- [ ] 技能路径负责展示学习顺序和证据要求。
- [ ] 每日简报只汇总计划任务、申请截止和面试安排。
- [ ] 所有计划任务都能关联到一个岗位、申请或能力差距。
- [ ] 避免同时生成多套互相独立的“目标计划”。

## 五、第四优先级：合并面试训练

- [ ] 题库作为公共内容入口保留。
- [ ] STAR 作为回答结构工具保留。
- [ ] AI 模拟面试和面试空间统一写入同一条面试训练记录。
- [ ] 报告、错题本和语音复盘作为训练记录的结果或附件。
- [ ] 面试结束后自动生成复练任务。
- [ ] 个人面经与公共题库分开标识，避免用户混淆。

## 六、资源中心调整：保持完整展示

- [ ] 保留原有完整目录和分组，不做折叠或点击展开。
- [ ] 每张卡片统一使用“适用场景 + 产出结果”的描述。
- [ ] 给重复感较强的功能增加关系说明，例如“用于申请包”“关联申请管线”。
- [ ] 资源卡片支持直接进入相关核心对象，而不是进入孤立工具页。
- [ ] 暂停继续增加新的独立 AI 工具入口。

## 七、暂缓扩张或降级处理

- [ ] 公司洞察：先验证数据来源和用户实际使用，再决定是否扩展。
- [ ] 职业趋势洞察：先作为内容模块，不进入主流程。
- [ ] 机构测评：保留结果，但不新增复杂流程。
- [ ] 泛资讯：保留资源属性，不与申请主线竞争首页位置。
- [ ] 通用 AI 聊天：作为底层能力，避免继续增加新的专家入口。

## 八、上线前必须补的验证能力

- [ ] 记录首次进入到首次有效动作的时间。
- [ ] 记录从岗位查看到创建申请的转化率。
- [ ] 记录从申请创建到生成申请包的完成率。
- [ ] 记录多个简历、规划和进度入口之间的来回跳转。
- [ ] 记录 AI 结果是否被保存、关联或再次使用。
- [ ] 记录面试训练后是否完成复练。
- [ ] 为“找不到入口”“不知道选哪个”“重复填写”增加反馈选项。

## 九、建议的验收标准

- [ ] 新用户能在 3 分钟内找到一个岗位并创建申请。
- [ ] 用户不需要理解“普通简历”和“申请材料”的产品差别。
- [ ] 一个申请可以看见所用简历、匹配结果、材料、面试和下一步任务。
- [ ] 从面试模拟到报告和错题复练不需要重新寻找入口。
- [ ] 资源页仍能直接看到全部工具。
- [ ] 没有核心功能因为本轮收敛而失去访问路径。

## 十、执行顺序

1. 先做对象和数据关系，不改资源目录。
2. 再合并简历与申请材料。
3. 再统一申请管线和状态。
4. 再合并规划与每日简报。
5. 最后合并面试训练和复练。
6. 运行 4–8 周小规模验证后，再决定哪些低频能力降级或下线。
