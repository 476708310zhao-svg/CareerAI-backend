# 职引：商业化运营与推广产品说明书

> 版本：讨论稿 v1.0｜2026-11-12
>
> 用途：统一产品介绍、首期商品边界、运营流程和推广口径，供产品、内容、客服、技术及合作方评审。
>
> 事实口径：依据当前主仓源码与开发记录整理；本文中的推广节奏和指标是**建议方案**，不是已取得的经营数据或已批准的预算。

## 1. 产品是什么

**一句话介绍：**职引是一款围绕具体岗位申请推进的 AI 求职小程序，帮助用户找机会、整理简历和申请材料、管理进度、准备笔试面试，并看清下一步要做什么。

用户主要是正在找实习或校招岗位的学生、应届生、留学生及早期职业求职者。产品面向多地区求职，但具体国家、职位来源和工作资格信息要按已核验的数据逐步开放，不把某一地区的规则当作全球通用规则。

**核心价值：**一次申请作为主线，岗位、简历版本、材料、待办和面试记录留在同一上下文中。用户能分清“AI 建议”“已保存到职引”和“本人已在招聘方网站执行”。职引不承诺录用，也不代用户自动投递。

### 对外可用的短介绍

> 职引帮你把求职过程整理成可执行的下一步：查看有来源的岗位，管理每条申请，准备简历与材料，练习笔试面试，并在重要节点获得提醒。AI 可以协助分析和起草，关键内容由你确认，最终投递由你本人完成。

这段介绍可用于小程序简介、合作介绍页和媒体资料；发布前应按实际上线版本删去尚不可用的功能。

## 2. 目标用户与使用场景

| 用户群 | 最迫切的问题 | 首次进入时应体验的路径 |
| --- | --- | --- |
| 正在寻找校招/实习机会的学生 | 信息分散、截止日容易遗漏 | 找岗位或校招 → 看来源和截止日 → 收藏/加入申请 |
| 同时申请多家公司的求职者 | 简历版本、材料和状态容易混淆 | 建立申请 → 绑定简历 → 补材料清单 → 更新下一步 |
| 准备测评和面试的用户 | 不清楚针对哪家公司准备 | 从申请或资源入口进入相关资料/练习 → 记录结果 |
| 跨地区求职的留学生 | 工作资格、地区和岗位要求难判断 | 完善画像 → 查看岗位事实与资格证据 → 自行判断并投递 |

首期推广应选择一个可用内容最完整的人群和场景验证，建议从**校招/实习岗位发现与申请跟进**开始，再扩展到简历、笔试和面试。不要同时对所有国家、所有岗位类型宣称完整覆盖。

## 3. 产品结构与当前可交付边界

小程序当前五个主入口是**首页、机会、AI求职、资源、我的**。完整申请进度从首页或个人相关入口进入。Web 工作台适合更完整的材料编辑和申请管理。

| 产品层 | 用户获得的价值 | 当前判断 |
| --- | --- | --- |
| 免费基础流程 | 岗位与校招浏览、收藏、申请进度、个人资料、部分内容和提醒 | 已有实现；新岗位来源与多端状态需要按候选版本和真机验收确认。 |
| AI 辅助 | 岗位解释、简历建议、材料/问答草稿、面试与职业规划 | 已有代码；模型结果、规则降级和额度应明确展示。简历 AI 真实成功路径仍需上线与真机复测。 |
| 单品测评资料 | 按公司查找资料，查看目录和说明；付款后在本人已购中领取网盘链接 | **现有明确商品价格为每份 ¥9.00**。后端有资料收款开放记录，但当前真实付款、通知、领取和小程序正式版状态需重新核验。 |
| 免费在线刷题 | 已授权题集的网页/小程序答题、提交后结果、错题及报告 | 代码存在；公开内容仍受真实授权、人工审核、私有 PDF 安全检查和设备验收约束。会员题集未开放。 |
| 会员/场景包 | 扩展 AI 或其他权益的候选商业模式 | 权益和订单基础存在；价格契约、资质、真实支付及退款验收未完成，当前不作为对外主推商品。 |
| 人工服务 | 简历优化、人工筛岗、申请协助的授权工单 | 本地实现了授权与撤销流程；服务范围、SLA、价格、人员能力和交付标准未定，暂不售卖。 |

商业化第一阶段围绕现有 **¥9 测评资料单品**展开。单品购买只授予该商品的领取权益，不自动获得会员或刷题权益。其他收费产品须在产品、价格、交付和售后都明确后另行上线。

## 4. 商业模式与商品说明

### 4.1 当前主推商品：单份测评资料

**用户购买前应看到：**适用公司与招聘季、资料名称、目录、样例、来源说明、更新日期、适用范围、固定价格 ¥9.00、领取方式、使用/更新/售后说明。没有真实资料或交付链接的商品不应上架。

**购买后承诺的交付：**订单经服务端确认后，购买者可在“我的已购”再次领取对应网盘链接和提取码；下架不应抹掉既有已付订单的合法领取记录。支付异常、链接失效、资料不符和退款撤权需要客服处理流程及审计记录。

**运营单元：**每份商品绑定真实公司及资料版本。上架前核对内容权利、目录与样例、链接有效性、招聘季、公司关联、支付 SKU 和售后文案；招聘季变化或链接失效时及时下架或更新，并保留历史购买快照。

### 4.2 后续可能的收入线

| 收入线 | 推进条件 | 当前动作 |
| --- | --- | --- |
| 会员订阅 | 权益差异、价格、周期、到期、退款和真实支付均清晰且可验收 | 先定义套餐和服务成本，再小范围验证；不先投广告。 |
| 付费题集 | 逐题具备相应的展示和商业使用权，内容审核、答案质量、撤权机制就绪 | 当前继续免费授权题集灰度；不得把购买 PDF 等同于题目商业授权。 |
| 人工服务 | 可重复的服务流程、交付样例、响应时限、授权撤销和售后能力 | 先做少量人工试点并记录工时与满意度，再定价。 |
| 校园或机构合作 | 可证明的用户价值、数据边界和合作资源 | 从内容共创与福利合作试点，不出售用户简历或申请数据。 |

任何新价格都属于待决策项，本文不虚构会员价、人工服务价或付费转化率。

## 5. 用户增长与转化路径

```text
内容/社群/搜索/合作触达
  → 进入对应场景页（岗位、校招、申请管理或测评资料）
  → 完成一个免费、有结果的动作
  → 保存申请或资料需求
  → 在需要时查看清楚的付费商品说明
  → 本人决定购买
  → 完成交付、复访与售后
```

免费体验的关键不是让用户多点入口，而是让用户完成一次真实的“下一步”。付费入口应出现在与具体需求相关的页面，展示可获得内容和价格；不以锁住已创建的申请或制造紧迫感逼迫付款。

### 首期建议验证的三个入口

1. **校招机会入口：**围绕具体公司、岗位和截止日制作可核验的内容，落到岗位/校招详情，促进收藏或加入申请。
2. **申请管理入口：**以“多家公司投递进度如何不乱”为主题，落到申请工作台，促进首条申请创建与下一步完成。
3. **测评准备入口：**以具体公司测评准备清单和免费样例吸引有明确需求的人，落到资料详情；只有真实可交付商品才展示购买。

## 6. 推广渠道与内容策略

| 渠道 | 适合的内容 | 进入小程序后的目标动作 | 先决条件 |
| --- | --- | --- | --- |
| 微信公众号/视频号/社群 | 校招时间线、岗位核验方法、申请管理实例、面试复盘 | 收藏岗位、建立申请或查看资料目录 | 内容有来源和更新时间；社群规则及用户意愿得到尊重。 |
| 小红书、抖音等内容平台 | 一分钟可操作的求职步骤、简历版本管理、测评准备方法 | 通过合规入口到对应场景页 | 内容是真实演示，不伪造成功案例或夸大 AI。 |
| 高校社团、留学生组织和职业发展合作 | 招聘季清单、公开讲座、免费工具体验 | 完成画像和首条申请 | 明确合作方与数据边界，收集反馈而非只追求扫码数。 |
| 微信内付费投放 | 已验证的单一场景与落地页 | 可归因的有效激活或付费成交 | 先有真实交付、埋点、成本和退款数据，再小预算试验。 |

腾讯广告公开资料列有朋友圈、公众号、小程序、视频号和搜一搜等广告资源位，但具体开户、可投类目、素材和落地页要求应在投放当期向平台核实。[腾讯广告营销学堂资料](https://training.tencentads.com/uploads/202406/44FVgzA9_zjy5jV.pdf)

**内容栏目建议：**

- 每周校招截止提醒：只发布来源可回查、时间仍有效的机会。
- 一条申请如何推进：展示真实操作方法和状态区分，不使用虚构用户经历。
- 简历与材料准备：讲清不同岗位如何选择版本及核对 AI 建议。
- 笔试/面试准备：免费方法论 + 有明确目录的资料样例。

每条内容附适用人群、发布日期或更新时间、来源、下一步操作和失效处理责任人。避免把企业官网岗位转载包装为“内部招聘”或“保录取渠道”。

## 7. 运营流程与职责

| 流程 | 操作要求 | 建议负责人 |
| --- | --- | --- |
| 岗位与校招 | 采集来源、核对申请链接、标记过期/异常、处理用户反馈 | 内容运营 + 数据维护 |
| 测评资料 | 权利与内容核验、公司绑定、样例和目录、链接测试、上架/下架 | 商品运营 + 审核人 |
| 订单与客服 | 查询订单、处理未到账/链接失效/退款、保存处理记录 | 客服 + 财务/运营 |
| AI 质量 | 抽查建议是否有依据、记录模型失败与降级、修复错误提示 | 产品 + 技术 |
| 增长实验 | 每个活动设唯一入口和参数，复盘激活、留存、成交及投诉 | 增长运营 + 数据分析 |

首批团队规模不明时，一人可以兼多项日常操作，但**商品内容审核、权利判断和公开发布**不能因人手少而跳过现有校验。涉及个人简历和申请的客服查看应以用户授权和最小权限为前提。

## 8. 指标体系与试验方法

**北极星指标建议：**每周完成至少一个真实求职下一步的活跃用户数。下一步可以是保存申请、完成材料、确认投递事实、完成任务或结束面试练习；单纯打开页面或发起 AI 对话不计入。

| 阶段 | 指标与计算口径 | 用途 |
| --- | --- | --- |
| 触达 | 各渠道到达用户、来源可归因比例 | 判断内容和合作是否带来目标人群。 |
| 激活 | 新用户首次完成“收藏/加入申请/建立任务”等有效动作的比例 | 判断落地页和免费价值是否清楚。 |
| 留存 | 首次有效动作后 7 天、30 天仍有有效动作的用户比例 | 判断用户是否持续推进求职。 |
| 商品 | 资料详情查看 → 下单 → 支付成功 → 本人领取的分步人数 | 定位价格、支付或交付阻塞。 |
| 单位经济 | 净收入 = 实收 − 退款；贡献毛利 = 净收入 − 支付费 − 内容/客服/模型等可归因变动成本 | 决定能否扩大投放。 |
| 质量 | 无法领取率、退款率、资料投诉率、失效岗位反馈率、AI 失败率 | 决定是否暂停推广和修复。 |

所有漏斗指标按唯一用户及明确事件口径计算；“点击官网申请”与“用户确认已提交”分开统计。没有完整回执或对账时显示“数据不足”，不展示推测的成交、录用或就业成功率。先用小流量自然渠道跑通数据，再制定数值目标和付费获客成本上限。

## 9. 分阶段商业化与推广计划

| 阶段 | 工作重点 | 进入下一阶段的条件 |
| --- | --- | --- |
| A. 产品与交付核验 | 固定发布版本；真机走通免费主链路及 ¥9 商品下单、支付回调、领取、退款；检查隐私、权利和客服流程 | 真实订单与交付可追踪，异常可处理，商品说明与实际一致。 |
| B. 小范围自然增长 | 选一个招聘季场景，发布有来源的内容，与少量社群/校园合作；逐条记录用户问题 | 能看到有效激活、复访和商品交付反馈，核心问题得到修复。 |
| C. 内容与渠道复制 | 保留表现好的主题和入口，扩充公司/岗位/资料；建立内容更新排期与客服知识库 | 内容维护能力、交付质量和单位经济可持续。 |
| D. 付费投放和新商品 | 对已证明有效的场景进行小预算投放；另行评审会员、付费题集或人工服务 | 获客成本、退款和投诉在事先确定的可接受范围内，再扩大预算。 |

具体预算与阶段日期需要以真实支付、转化和服务成本数据制定。现阶段不建议给出无依据的收入预测。

## 10. 对外宣传与上线核对

- **功能真实性：**广告、商品页和宣传材料只展示当前正式版可用功能；后端有代码不等于小程序已发布。
- **结果真实性：**不写“保证 offer”“提高录用率 X%”“已帮助 X 人上岸”等没有证据的承诺；岗位匹配分、AI 评分和模拟面试报告不等于招聘结果。
- **商品透明：**价格、资料目录、交付方式、适用范围、更新与售后说明在付款前清楚展示。广告对商品和服务的描述应真实、准确、清楚。[《中华人民共和国广告法》](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_5474cf75173c45d6a0379730fb4e8d97.html)
- **投放识别：**商业推广内容按实际渠道要求标识并留存素材与审核记录；互联网广告适用真实、合法等要求。[《互联网广告管理办法》](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2023/art_d93a579afd45413e8576e4623fab348f.html)
- **支付平台复核：**虚拟商品的支付方式、主体资质、iOS/Android 展示、SKU 和回调配置，正式上线前以微信公众平台当期规则和审核结果为准。微信开发者文档页面本次无法稳定读取，本文不据第三方转述作平台规则结论。
- **内容与个人数据：**资料、题目和图片取得相应处理、展示与商业使用权；求职简历与申请信息只按授权及最小权限使用，不用作广告定向名单或合作方交付素材。

## 11. 当前需要产品负责人确定的事项

1. 首期聚焦的人群、招聘季和地区，以及对应岗位/资料的真实供给量。
2. ¥9 资料的首批可售清单、权利证明、维护责任人、售后响应时限及退款处理标准。
3. 正式小程序与后端的当前版本、真实支付验收结果，以及哪些页面可对外宣传。
4. 免费能力与未来会员权益的清晰分界；会员、人工服务和付费题集暂不填写价格。
5. 自然渠道首批合作对象、内容产能、可接受的客服量与后续投放预算上限。
