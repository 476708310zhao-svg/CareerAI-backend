## 1. 目标与范围

用户找到校招测评资料，了解内容后购买，支付成功后直接领取网盘链接和提取码，到网盘查看或下载。

```text
首页热门三公司 ──────────────→ 商品详情 → 购买 → 网盘链接和提取码
首页「查看全部」/资源中心 → 商品列表 ──↑                  ↑
公司详情的资料卡片 ──────────────────↑         我的已购 → 再次领取
```

1.0 只做商品展示、公司关联、详情、单品购买、链接领取、已购记录和基础运营后台。

站内阅读器、PDF 预览、在线练习、学习进度、收藏笔记、错题本/OA 联动、AI、购物车、优惠券和复杂内容版本管理均后置。所有资料由运营提前整理到网盘，每次购买一个商品，数量固定为 1。

## 3. 用户端需求

### 3.0 首页「热门测评资料」

#### 位置与目的

- 使用用户提供的“最新机会”截图作为该模块的视觉参考：一个白色圆角大卡片，内部是紧凑的纵向列表。
- 默认放在「最新机会/为你推荐」之后、「每日最新校招」之前。岗位模块未展示时，资料模块仍在校招模块之前，不依赖岗位招聘开关。
- 左侧标题「热门测评资料」，右侧「查看全部 >」。首页只展示摘要，不在此执行购买或领取。
- 目标：用户从首页一眼识别目标公司资料，点击一次进入对应商品详情。

#### 内容结构

```text
┌────────────────────────────────────┐
│ 热门测评资料              查看全部 > │
│ [图标] 公司 A · 校招测评资料       > │
│        适用届别 · 一句话内容说明     │
│        ¥9.00                       │
│ ────────────────────────────────── │
│ [图标] 公司 B · 校招测评资料       > │
│        适用届别 · 一句话内容说明     │
│        ¥9.00                       │
│ ────────────────────────────────── │
│ [图标] 公司 C · 校招测评资料       > │
│        适用届别 · 一句话内容说明     │
│        ¥9.00                       │
└────────────────────────────────────┘
```

以上公司为占位示意。实际名称、公司、图片、价格和适用届别必须来自商品及公司数据，价格统一为 9 元，不预设哪三家公司热门。

| 行内元素 | 展示规则 |
|---|---|
| 公司图标 | 使用公司 Logo，加载失败用公司首字/通用公司图标，不显示破图 |
| 主标题 | 优先使用简短商品名，必须让用户识别公司；单行省略，详情展示完整名称 |
| 辅助信息 | 适用届别 + 简短内容摘要；无届别则只展示摘要，不编造年份 |
| 价格 | 读取服务端商品售价 900 分，展示 ¥9.00；不展示虚构划线价 |
| 箭头 | 右侧固定，提示进入详情；整行可点击 |

沿用首页现有卡片宽度、圆角、文字色、内边距和行分隔线。公司图标和右箭头保持固定宽度，中间文本可收缩省略；不使用横滑、自动轮播或三张大封面卡。点击区域不小于 44px，长名称与价格不能相互遮挡。以 390×844 为主验收视口，并检查 320/375/430px 宽度。

#### 热门三家公司选择规则

1. 1.0 由运营按真实咨询、搜索需求和招聘季判断配置，手动选出最多 3 组「公司 + 主推商品」并排序；不开发自动热度算法。
2. 三条对应三家不同公司，每家公司只展示一份资料；同一商品也不重复展示。
3. 主推商品必须处于在售状态，并已关联所选公司；后台保存时校验。
4. 前端展示顺序以服务端推荐顺序为准，不按商品名或本地数据重新排序。
5. “热门”表示运营选出的高频需求资料，不显示“销量前三”“已有多少人购买”等无数据依据的排名声明。

#### 点击与返回

- 点击资料整行 → 该资料商品详情，传递 `productId`、`source=home_assessment`、来源 `companyId` 和展示位置 1–3。
- 点击「查看全部」 → 完整测评资料列表，不加某家公司筛选。
- 详情返回首页时保留原滚动位置；从列表进入详情后返回原列表和搜索结果。
- 未登录可查看首页和详情，点击购买才登录；首页不为获取已购标记而强制登录，已购状态在详情按当前账号校验。
- 公司 Logo 不单独跳公司详情，整行保持单一目的地，避免误触。

#### 加载与边界

| 场景 | 行为 |
|---|---|
| 3 个有效配置 | 展示三家公司 |
| 只有 1–2 个有效配置 | 按实际数量展示，不补假资料或重复公司 |
| 无配置/全部下架/模块关闭 | 不展示首页模块，完整列表入口仍由资源中心承接 |
| 请求失败 | 隐藏该模块，不阻塞今日计划、岗位和校招加载；后续进入首页可重试 |
| 缺图/图片失败 | 用默认图标，仍能进入商品详情 |
| 展示后商品下架或改价 | 进入详情重新读取；下架停止新购，改价按最新信息确认 |
| 老请求在离开页面后返回 | 不覆盖新页面状态，不错误跳转 |

该模块独立异步加载，不作为首页其他数据成功展示的前置条件。1.0 不做持久本地推荐缓存，返回首页时重新拉取；后台上下架或调整推荐后，下次读取生效。返回保留滚动位置与重新读取数据可同时实现。

### 3.1 商品列表

- 标题为「测评资料」，支持搜索商品名称、关联公司名称。
- 卡片展示封面、名称、公司标签、简短介绍、价格；已购商品显示「已购买」。
- 默认按后台设置顺序展示，首期不做多条件筛选和销量排序。
- 点击进入商品详情；已购用户仍可查看介绍和领取。
- 空列表显示「资料正在整理中」；搜索无结果可清空关键词。

### 3.2 公司下挂资料

- 公司详情增加「测评资料」区块，展示封面、商品名、价格和详情入口。
- 有关联在售商品时显示，最多 3 个；超过 3 个显示「查看全部」，进入该公司的商品列表。
- 无关联在售资料时隐藏整个区块。
- 一家公司可挂多个商品，一个商品也可关联多家公司；后台通过公司 ID 配置。
- 公司入口与独立列表使用相同商品 ID、价格和购买状态。
- 记录购买来源公司，不要求用户先建立求职申请。

### 3.3 商品详情

页面顺序：

1. 封面、商品名称、适用公司/招聘季和售价。
2. 简介：适合谁、能获得什么资料。
3. 资料目录：文本列出文件和内容，如「测评流程说明、数理推理练习、参考解析」。
4. 示例图：可选，运营上传若干公开图片，不开发独立样章系统。
5. 交付方式：「付款后领取网盘链接和提取码，请在对应网盘查看或保存」。
6. 使用、领取、更新与售后四项统一说明：后台一次配置，所有商品继承；单品领取天数和来源仍单独维护，购买前展示。
7. 底部固定操作栏：价格 +「立即购买」；有效已购用户改为「领取资料」。

商品出售的是详情列明的资料包；更新范围与领取期限由运营明确填写，不默认承诺永久免费更新。内容介绍不填写虚构销量、原价或无依据的“内部原题”“保过”等内容。

### 3.4 购买

- 浏览无需登录，点击购买时登录，成功后继续原商品操作。
- 点击「立即购买」显示简短确认层：名称、实付金额、网盘交付说明；确认后拉起可用支付渠道。
- 服务端校验商品统一价格 900 分及用户确认的共享说明版本，保存商品名称、金额、资料包标识、领取期限、四项说明及版本的订单快照；版本变化返回409要求刷新确认。
- 同一用户已购买且未退款的商品不重复收费，直接进入领取页。
- 连续点击复用有效待支付订单；已有已支付订单时返回领取入口。
- 前端支付返回后进入订单与领取页；服务端确认收款后才显示链接。
- 回调延迟时显示「支付结果确认中」，支持刷新，不提前发链接。
- 取消或失败返回详情，可重试；商品下架或报价已过期后须刷新确认，旧待支付订单失效。迁移为 9 元时关闭旧金额待付订单，历史已付金额和快照保留。

支付底层复用项目已有能力；测评资料 SKU 和订单分支需要新增，不能直接把商品 ID 当作会员套餐 ID。具体收款渠道以实施时已有可用配置为准。

### 3.5 自动交付网盘链接

1.0 将“发送给用户”定义为：**付款后自动展示领取信息，保留已购入口再次查看**。用户不需要等待客服人工发货，首期不接短信、邮件或微信私信通知。

订单与领取页展示：

- 商品名称、订单号、付款金额、购买时间；
- 网盘名称、链接和提取码（如有）；
- 「复制链接和提取码」主按钮；
- 「复制后打开对应网盘 App 或浏览器，粘贴链接使用」说明；
- 「链接失效？联系客服」入口。

复制内容示例：

```text
资料：XX 公司 2027 校招测评准备资料
链接：<运营配置的网盘链接>
提取码：<如有>
使用方法：打开对应网盘，保存后查看。
```

链接由运营预先配置。服务端确认付款后自动向本人领取接口提供链接和提取码；商品详情、分享卡片、未支付订单均不包含这些字段。

1.0 以复制方式交付，不依赖小程序直接打开外部网盘。

### 3.6 我的已购与售后

- 按购买时间倒序显示已支付资料：封面、名称、购买时间、「领取资料」。
- 未购买时展示空态和「去看看资料」。
- 有效已购用户换设备或重新登录后可再次领取，无需重新购买。
- 商品普通下架仅停止新购，不影响已有订单在所购领取期限内领取。
- 链接失效时走现有客服；运营修正链接后，有效已购订单可重新领取。
- 退款走现有人工处理流程；完成后保留订单记录并显示「已退款」，不再返回链接。
- 首期不新建售后工单、自助退款和学习资产管理系统。

网盘共享链接复制后可能被保存、转发或下载。退款后只能停止平台再次提供领取信息，无法撤回已复制的链接或已下载文件。

## 4. 运营后台

### 4.1 一个商品表单

| 字段 | 要求 |
|---|---|
| 名称、封面、简介 | 必填 |
| 售价 | 固定 9 元，以 900 分存储，后台只读不可改 |
| 关联公司 | 多选，通用资料可不关联 |
| 首页推荐配置 | 最多 3 组公司 + 主推商品；调整顺序，校验公司/商品不重复且在售 |
| 招聘季/适用届别 | 文本或标签 |
| 详细介绍、资料目录 | 必填 |
| 示例图 | 可选 |
| 网盘名称、链接、提取码 | 名称/链接必填，提取码按需 |
| 使用、领取、更新和售后说明 | 商品自动继承后台“统一说明”，全商品一次配置，非单品表单/飞书每行必填字段；配置完整后可上架 |
| 来源说明 | 记录提供方与资料来源 |
| 状态、排序 | 草稿 / 在售 / 下架，运营设置顺序 |

支持新增、编辑、上架、下架，售价固定为 9 元。上架前检查介绍和链接可用性；链接单独保存，不写进公开富文本。编辑交付信息记录操作者与时间。

同一资料包的链接纠错可同步给有效已购订单；实质不同的资料包新建商品，不覆盖旧订单内容。

首页推荐在商品管理中用一个小配置区维护，无需新建推荐平台。支持模块启用/关闭、选择公司及主推商品、排序；下架后服务端自动过滤对应条目。关闭首页推荐不影响商品详情、资源列表和已购领取。

### 4.2 一张订单列表

- 按订单号、用户、商品、状态查询。
- 查看服务端支付结果与交付状态。
- 已付款但交付失败时可重试；不重复扣款或创建购买记录。
- 网盘链接统一在商品表单中修正，不逐单人工发送。
- 复用现有人工退款记录，不允许直接将未支付订单编辑为已支付。

## 5. 最小数据与接口

以下均为待开发设计，不表示当前已上线。

### 5.1 最小数据增量

- 商品：公开介绍、价格、状态、网盘交付配置、更新时间。
- 商品与公司关联：商品 ID、真实公司 ID，多对多。
- 首页推荐配置：启用状态、最多 3 个 `{ companyId, productId, sortOrder }` 项；优先使用现有配置存储方式，不为此建设推荐算法服务。
- 订单扩展：商品 ID、购买快照、用户、支付记录、来源入口/公司。
- 交付记录：订单号、商品 ID、交付状态、领取期限和交付时间；同一订单只创建一次。

复用现有订单与账本，数据库增量通过 migration 实施。不建章节、题目、学习进度和复杂版本表。

### 5.2 拟新增接口

| 接口草案 | 用途 |
|---|---|
| `GET /api/v4/assessment-products/home` | 匿名首页入口；服务端过滤、去重、排序，最多返回三项 |
| `GET /api/v4/assessment-products?keyword=&companyId=` | 公开商品列表、搜索和公司筛选 |
| `GET /api/v4/assessment-products/:id` | 公开详情，不返回网盘字段 |
| `POST /api/v4/assessment-orders` | 登录后服务端定价下单，含防重复键 |
| `GET /api/v4/assessment-orders/:orderNo` | 本人订单和交付状态 |
| `GET /api/v4/assessment-purchases` | 本人已购商品 |
| `GET /api/v4/assessment-orders/:orderNo/delivery` | 已付款且有效的本人链接/提取码 |
| 后台商品管理与订单查询接口 | 沿用现有后台鉴权，路由实施时确定 |

支付确认与回调复用已有机制并扩展商品分支，不新建第二套回调。业务响应使用统一格式，小程序通过统一 API Client 调用。

### 5.3 异常与边界

| 场景 | 处理 |
|---|---|
| 支付取消/失败 | 不发链接，可重试 |
| 支付待确认 | 显示确认中，可刷新订单 |
| 已付款、交付异常 | 显示「已付款，资料领取暂不可用」，提供重试和客服 |
| 商品下架 | 停止新购，已有有效购买可领 |
| 退款完成/领取期限届满 | 保留订单，不返回链接 |
| 链接失效 | 客服反馈，运营修正后再次领取 |
| 其他用户访问订单 | 拒绝，不返回订单或交付内容 |

领取接口校验登录用户、订单归属、已付款和领取有效性。重复支付通知不重复交付；退款后迟到的支付通知不得恢复领取权限。
