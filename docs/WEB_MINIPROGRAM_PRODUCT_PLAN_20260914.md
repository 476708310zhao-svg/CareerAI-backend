# 官网 Web 与小程序产品规划

更新时间：2026-09-14

## 一、规划依据

用户反馈的真实链路是：

> 电脑看校招信息、标星、整理并投递；手机刷题、临时复习和接收提醒。

因此两端不再追求功能完全一致，而是围绕同一套求职数据提供不同操作方式：

- 官网 Web：求职管理主工作台，适合长时间、批量、对比和编辑。
- 微信小程序：移动求职助手，适合快速查看、记录、刷题、提醒和面试前准备。

两端共用岗位、申请、简历资产、求职计划和面试记录，不复制业务数据。

## 二、两端的核心定位

### 官网 Web：管理和产出

Web 首屏只回答三个问题：

1. 我现在有哪些申请需要处理？
2. 哪些申请临近截止或需要跟进？
3. 今天最应该完成哪一项准备？

主要操作：

- 多岗位搜索、筛选、比较和批量标星；
- 申请看板和表格管理；
- 简历版本、JD、ATS 和申请材料并排处理；
- 联系人、面试安排、Offer 和备注集中维护；
- 查看漏斗、复盘报告和求职计划。

### 小程序：查看和行动

小程序首屏只突出 Today 工作台：

- 今日截止和面试提醒；
- 今日待办和复练任务；
- 最近申请状态；
- 一键进入刷题或模拟面试。

主要操作：

- 快速查看岗位和申请状态；
- 收藏、记录跟进结果和补充备注；
- 面试前刷题、练 STAR、模拟回答；
- 接收状态、截止和复习提醒；
- 在没有电脑时完成轻量更新。

## 三、官网 Web 信息架构

### 1. 工作台

聚合申请数量、临近截止、面试安排、待办和最近活动。主按钮为“处理下一项任务”，不再展示完整工具宫格。

### 2. 校招与职位

保留校招信息、职位搜索、筛选、标星和岗位详情。桌面端增加：

- 表格/卡片切换；
- 多选岗位后批量加入申请管线；
- 岗位对比；
- 来源、新鲜度、截止日期和 Job Trust 风险并排展示。

### 3. 申请管理

这是 Web 的核心页面，支持看板和表格两种视图：

- 已收藏、准备中、已投递、笔试中、面试中、Offer、已结束；
- 公司、岗位、截止日期、下一步行动、负责人备注；
- 批量修改状态、设置日期和归档；
- 点击一条申请进入完整详情。

### 4. 申请详情与申请包

一条申请集中展示：

- 岗位和 JD；
- 匹配结果和身份/Sponsor 约束；
- 使用中的简历版本和 ATS 结果；
- Cover Letter、Recruiter 消息、Follow-up 等材料；
- 联系人、面试空间、面试报告、Offer 和下一步任务。

### 5. 简历与材料

采用桌面双栏：左侧经历库和简历版本，右侧目标岗位、JD 差距、AI 建议和申请材料。所有 AI 修改继续逐条确认，不直接覆盖原文。

### 6. 面试复盘

按申请和岗位查看 Interview Brief、训练记录、报告、错题和语音复盘。题库与 STAR 作为“准备素材”进入训练，不与历史记录混在同一列表。

### 7. 求职计划

展示竞争力差距、阶段任务、Today 任务和周复盘。Web 端负责调整和查看，移动端负责完成和延期。

## 四、小程序信息架构调整

小程序现有一级导航继续保留，但重新定义职责：

| 一级入口 | 只负责什么 |
|---|---|
| 首页 | Today、提醒和最近任务 |
| 校招 | 查看、收藏和快速进入申请 |
| 资源 | 完整直出所有准备工具，不折叠、不隐藏 |
| 进度 | 快速查看和更新申请状态 |
| AI 专家 | 在已有岗位或申请上下文中进行 AI 处理 |
| 我的 | 资料、简历入口、历史和设置 |

移动端不再承担复杂的批量管理、长文编辑和多岗位横向对比。

## 五、功能迁移优先级

### Web 第一阶段：申请管理 MVP

- 网页登录/注册和登录态保护；
- 工作台概览；
- 申请列表、筛选、排序和状态修改；
- 申请详情；
- 截止日期和下一步行动；
- 与小程序实时共用申请数据。

### Web 第二阶段：申请包工作区

- 简历版本选择；
- JD 匹配和 ATS 结果；
- 申请材料生成、编辑和确认；
- 岗位、简历和申请材料的关联展示。

### Web 第三阶段：面试和计划

- Interview Brief；
- 面试记录和报告；
- 错题、复练和语音附件；
- 计划任务和周复盘。

### 暂缓搬迁

- 机构测评；
- 泛资讯；
- 薪资探索；
- 复杂语音和数字人面试；
- 更多独立 AI 专家入口。

## 六、技术复用和新增工作

可直接复用：

- `/api/users/web-login`、`/api/users/web-register`；
- `/api/v4/applications`；
- `/api/v4/resumes` 和申请材料接口；
- `/api/v4/interviews`；
- `/api/v4/today`、Networking、Career Coach 接口。

需要新增：

- 面向用户的 Web 前端目录和路由；
- Web Token 保存、刷新、退出和权限拦截；
- 申请表格、看板和双栏编辑器；
- 桌面端文件上传、预览和下载；
- Web 操作埋点和跨端验收；
- 统一申请上下文，避免从不同入口产生重复记录。

## 七、验收指标

首期不以页面数量验收，而看以下结果：

- 新用户 3 分钟内能找到一个岗位并加入申请管线；
- 用户能在电脑端一次处理 5 条以上申请；
- 一条申请可以看见简历、匹配、材料、面试和下一步；
- 用户从电脑切到手机后不需要重新填写公司和岗位；
- 面试训练后能在手机上完成复练；
- 申请状态、任务和提醒在两端保持一致。

## 八、最终分工

官网 Web 是“求职管理中心”，承担复杂信息整理和长期资产沉淀；小程序是“随身求职助手”，承担提醒、快速更新和面试前练习。产品功能不需要在两端各做一遍，所有新增功能先判断它属于管理、产出还是移动行动，再决定放在哪一端。
