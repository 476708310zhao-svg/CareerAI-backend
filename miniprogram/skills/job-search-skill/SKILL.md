# 职引岗位搜索 Skill

## 业务流程

用户提出找工作、找实习或筛选签证友好岗位
→ 调用 `searchJobs`
→ 展示岗位列表卡片
→ 用户点击某个岗位
→ 调用 `getJobDetail`
→ 展示岗位详情卡片
→ 用户进入职引现有岗位详情页。
→ 用户主动点击“用我的在线简历看匹配”后，在岗位详情页比较真实岗位描述与当前在线简历，并展示原文依据。

## 强制约束

1. `jobId` 必须来自 `searchJobs` 返回结果。
2. 禁止根据自然语言编造 `jobId`。
3. 禁止编造岗位、公司、薪资、签证支持情况和更新时间。
4. 用户未提供全部筛选条件时，只使用用户明确表达的条件。
5. 用户说“留学生可投”或“签证友好”时，仅使用岗位描述中明确肯定的 `OPT`、`CPT`、`H-1B` 或 `E-Verify` 表述；E-Verify 不等于签证担保。
6. 没有匹配结果时，应建议调整关键词、地区、城市、岗位类型或更新时间。
7. `searchJobs` 成功后必须展示岗位列表卡片。
8. `getJobDetail` 必须使用上游真实 `jobId`。
9. 第一阶段不允许自动投递。
10. 搜索与展示阶段不读取用户简历；仅在用户主动点击个人匹配后由现有岗位详情页读取当前账号在线简历，不将简历内容交给岗位搜索模型。
11. 第一阶段不做批量收藏。
12. 岗位数量只表示本次已获取并筛选的结果，不声称是全平台岗位总数；来源不可用与真实筛选为空必须区分。
13. 个人匹配的每项判断必须引用岗位描述和简历原文；简历未体现不等于用户没有该技能。不得编造学历、经历或签证资格。
14. `global` 每次只抽样部分国家；必须说明实际检索的国家。用户明确说美国、英国、中国内地、香港或加拿大时传入该地区，不把香港并入中国内地。
15. 香港政府开放数据若只给出职位编号和官方列表地址，不得称其为直接申请链接；提示用户按编号到官方列表核对资格。

## 已复用接口

- 岗位列表：`GET /api/jobs/aggregate`
- 岗位详情：优先 `GET /api/jobs/detail?job_id=...`，必要时兜底 `GET /api/jobs/:id`

## 页面

- 岗位列表页：`/pages/jobs/jobs`
- 岗位详情页：`/package-user/pages/job-detail/job-detail?id={jobId}`
